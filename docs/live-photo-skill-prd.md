# Product Requirements Spec: Real Photo for a Live Catalog Product (Skill Invoke)

Board item: [[kanban]] → Todo: "Give a live catalog product a real photo via `$swap-product-card-photo`"

## Objective

Replace the placeholder (picsum) image of one real catalog product with an actual
product photo, by following the repo's own skill — proving the team can change
production-facing content through the documented, test-guarded path.

## Context

The repo already resolves product photos through `Product::imageUrl()`: a local file
at `public/images/products/{rawurlencode(SKU)}.jpeg` wins; otherwise the SKU-seeded
picsum fallback renders. A previous exercise shipped a photo for SKU `XH-5832` — a
SKU that only exists in local seed data, so the live site never showed it. The lesson
this ticket closes: **a display name is not an identifier, and local data is not live
data.** This time, the SKU must come from the real record.

## Scope

- One product, identified by its **live** SKU (inspect the live catalog or database —
  do not assume from a product's display name or local seed data).
- Photo sourced or generated by the team, saved as
  `public/images/products/{rawurlencode(SKU)}.jpeg`.
- No changes to `Product.php`, the card component, or the catalog view — the
  resolver already handles the swap.

Out of scope: bulk photo replacement, admin upload UI, image optimization pipeline.

## Requirements

### 1. Follow the skill

Open and follow `skills/swap-product-card-photo/SKILL.md` end to end — including its
step 1 (read `AGENTS.md`, this docs folder, and the board before editing).

Acceptance: the workflow steps are followed as written; deviations are called out in
the PR description.

### 2. Target a real record

Pick the product by its SKU as it exists in the **live** data, verified against the
live catalog page — not the local seeder output.

Acceptance: the PR description names the SKU and where it was verified.

### 3. Photo through the resolver only

The photo lands at the resolver's expected path; no view or model edits.

Acceptance: `git diff` shows only the new image file (+ test if extended).

## Definition of Done

- [ ] `ProductCardPhotoTest` (or a focused extension of it) passes locally.
- [ ] Full backend suite run (`composer test`); any unrelated failure reported, not
      claimed as passing.
- [ ] PR opened from a branch (not a fork), board line moved per the kanban workflow.
- [ ] After merge + deploy, the **live products page** shows the real photo for that
      SKU — verified by loading the page, not by git history.
